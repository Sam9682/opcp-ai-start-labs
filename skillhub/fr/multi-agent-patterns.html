Systèmes multi-agents : quatre patrons d'architecture

Après-midi · Conception et gouvernance ⏱ ~45 min

Quand un seul agent ne suffit pas, on décompose le problème entre plusieurs agents spécialisés. Cette leçon explique pourquoi le faire, les quatre patrons d'architecture pour organiser plusieurs agents, et comment ils communiquent.

Objectifs pédagogiques

  • Expliquer pourquoi et quand décomposer une tâche entre agents
  • Reconnaître les quatre patrons d'architecture multi-agents
  • Décrire comment les agents communiquent entre eux

Pourquoi décomposer ?

  • Spécialisation — un agent ciblé, avec une boîte à outils et une invite étroites, surpasse un généraliste sur sa sous-tâche.
  • Séparation des responsabilités — des agents plus petits sont plus faciles à tester, à borner et à raisonner.
  • Parallélisme — des sous-tâches indépendantes s'exécutent en même temps.
  • Permissions restreintes — chaque agent reçoit uniquement les outils et portées requis, réduisant le rayon d'impact.

Les quatre patrons

1. Superviseur (orchestrateur–ouvrier)

Un agent superviseur décompose l'objectif et délègue des sous-tâches à des agents ouvriers, puis intègre leurs résultats. Sur opcp-explorer, un superviseur pourrait déléguer « construire l'image » et « vérifier la santé » à deux ouvriers.

flowchart TD
    S[Superviseur] --> W1[Ouvrier : déployer]
    S --> W2[Ouvrier : vérifier]
    W1 --> S
    W2 --> S

2. Pipeline (séquentiel)

Les agents sont disposés en chaîne ; la sortie de chacun est l'entrée du suivant. Idéal pour des flux étagés où l'ordre compte.

flowchart LR
    A[Planifier] --> B[Déployer] --> C[Vérifier] --> D[Rapporter]

3. Parallèle (éclatement / regroupement)

Un coordinateur éclate une tâche vers plusieurs agents travaillant simultanément, puis agrège (regroupe) leurs résultats. Idéal pour des sous-tâches indépendantes comme vérifier la santé de nombreuses apps en même temps.

flowchart TD
    C[Coordinateur] --> A1[Agent 1]
    C --> A2[Agent 2]
    C --> A3[Agent 3]
    A1 --> M[Agréger]
    A2 --> M
    A3 --> M

4. Réseau (pair-à-pair)

Les agents communiquent en pairs sans contrôleur central, négociant ou votant pour aboutir à un résultat. Le plus flexible, le plus difficile à gouverner et à déboguer.

flowchart LR
    P1[Agent A] <--> P2[Agent B]
    P2 <--> P3[Agent C]
    P1 <--> P3

Communication inter-agents

Quel que soit l'agencement des agents, ils échangent de l'information via l'un de ces mécanismes :

  • Messages — requêtes/réponses structurées passées directement entre agents.
  • Mémoire partagée / tableau noir — un stockage commun que les agents lisent et écrivent.
  • Résultats d'outils — la sortie d'un agent exposée à un autre comme un outil.
  • Transfert (handoff) — un agent transfère le contrôle (et le contexte) à un autre.

Des schémas de messages clairs et des transferts explicites gardent les systèmes multi-agents observables — ce qui importe pour la leçon sur les garde-fous.

Points clés à retenir

  • Décomposer pour la spécialisation, la séparation, le parallélisme et les permissions restreintes.
  • Quatre patrons : superviseur, pipeline, parallèle, réseau.
  • Les agents communiquent via messages, mémoire partagée, résultats d'outils ou transfert.
