Multi-Agent Systems: Four Architectural Patterns

Afternoon · Design & Governance ⏱ ~45 min

When one agent is not enough, you decompose the problem across several specialized agents. This lesson explains why you would do that, the four architectural patterns for arranging multiple agents, and how they communicate.

Learning Objectives

  • Explain why and when to decompose a task across agents
  • Recognize the four multi-agent architectural patterns
  • Describe how agents communicate with one another

Why Decompose?

  • Specialization — a focused agent with a narrow toolset and prompt outperforms a generalist on its subtask.
  • Separation of concerns — smaller agents are easier to test, bound, and reason about.
  • Parallelism — independent subtasks run concurrently.
  • Scoped permissions — each agent gets only the tools and scopes its job requires, shrinking the blast radius.

The Four Patterns

1. Supervisor (Orchestrator–Worker)

A supervisor agent decomposes the goal and delegates subtasks to worker agents, then integrates their results. On opcp-explorer, a supervisor might delegate "build the image" and "verify health" to two workers.

flowchart TD
    S[Supervisor] --> W1[Worker: deploy]
    S --> W2[Worker: verify]
    W1 --> S
    W2 --> S

2. Pipeline (Sequential)

Agents are arranged in a chain; each one's output is the next one's input. Good for staged workflows where order matters.

flowchart LR
    A[Plan] --> B[Deploy] --> C[Verify] --> D[Report]

3. Parallel (Fan-out / Fan-in)

A coordinator fans a task out to several agents working at once, then aggregates (fans in) their results. Good for independent subtasks like checking many apps' health simultaneously.

flowchart TD
    C[Coordinator] --> A1[Agent 1]
    C --> A2[Agent 2]
    C --> A3[Agent 3]
    A1 --> M[Aggregate]
    A2 --> M
    A3 --> M

4. Network (Peer-to-Peer)

Agents communicate as peers without a central controller, negotiating or voting to reach an outcome. Most flexible, hardest to govern and debug.

flowchart LR
    P1[Agent A] <--> P2[Agent B]
    P2 <--> P3[Agent C]
    P1 <--> P3

Inter-Agent Communication

However agents are arranged, they exchange information through one of a few mechanisms:

  • Messages — structured requests/responses passed directly between agents.
  • Shared memory / blackboard — a common store agents read and write.
  • Tool results — one agent's output exposed to another as a tool.
  • Handoff — one agent transfers control (and context) to another.

Clear message schemas and explicit handoffs keep multi-agent systems observable — which matters for the guardrails lesson.

Key Takeaways

  • Decompose for specialization, separation, parallelism, and scoped permissions.
  • Four patterns: supervisor, pipeline, parallel, network.
  • Agents communicate via messages, shared memory, tool results, or handoff.
