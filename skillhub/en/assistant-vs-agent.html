From Assistant to Agent: the Autonomy Spectrum

Morning · Fundamentals ⏱ ~30 min

This first lesson draws the line between an AI assistant and an AI agent, and introduces the autonomy spectrum you will use to decide how much freedom to grant a system. Throughout the session, the opcp-explorer platform is the environment an agent acts on — deploying, starting, and managing applications through its API, CLI, and MCP interfaces.

Learning Objectives

  • Differentiate an AI assistant from an AI agent
  • Place a system on the autonomy spectrum
  • Choose an appropriate level of autonomy for a given task and risk profile

Assistant vs Agent

The core difference is who drives the loop. An assistant responds to a single request and then stops. An agent pursues a goal: it decides what to do next, acts, observes the outcome, and repeats until the goal is met or a stopping condition fires.

DimensionAssistantAgent
InitiativeReacts to each promptPursues a goal across many steps
Control of the loopHuman drives every turnSystem drives its own turns
Tool useSuggests or noneCalls tools and acts on results
MemoryMostly the current turnShort-term + long-term state
StoppingAfter one answerOn goal, limit, or guardrail
Example on opcp-explorer"Explain how to deploy an app""Deploy and verify this app, retry on failure"

The Autonomy Spectrum

Autonomy is not binary. It runs along a spectrum from fully supervised to fully autonomous. Each step grants the system more freedom and removes a point of human control, so each step must be justified by lower risk or stronger guardrails.

  1. Suggest — the system proposes; a human performs every action.
  2. Confirm each step — the system acts, but a human approves before each action.
  3. Act with checkpoints — the system runs multiple steps, pausing at defined checkpoints for approval.
  4. Act and report — the system completes the task autonomously and reports afterward; a human can intervene or revert.
  5. Fully autonomous — the system acts without human review inside its granted scope.
Rule of thumb: grant the least autonomy that still lets the agent accomplish the task. Higher autonomy demands stronger guardrails — the five layers you will study this afternoon.

Mapping Autonomy to opcp-explorer

On opcp-explorer, the same operation can sit at different points on the spectrum:

  • Confirm each step — the agent proposes a deployment; an operator approves before it runs.
  • Act with checkpoints — the agent deploys to staging automatically but pauses before promoting to production.
  • Act and report — the agent restarts a crashed application and logs what it did.

Key Takeaways

  • An assistant answers; an agent pursues a goal by driving its own loop.
  • Autonomy is a spectrum, not a switch.
  • Choose the lowest autonomy that gets the job done, and match it with guardrails.
