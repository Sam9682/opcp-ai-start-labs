The Agentic Loop: Think → Act → Observe

Morning · Fundamentals ⏱ ~45 min

What makes an agent an agent is the loop. Rather than answering once, the agent repeatedly thinks about what to do, acts, and observes the result — feeding each observation back into the next decision. This lesson covers the base loop and three widely used variants.

Learning Objectives

  • Describe the Think → Act → Observe cycle and its data flow
  • Compare ReAct, Plan-and-Execute, and Reflexion
  • Choose a loop variant for a task on opcp-explorer

The Base Loop

flowchart LR
    Think[Think: reason about the goal and next step]
    Act[Act: call a tool]
    Observe[Observe: read the result]
    Think --> Act --> Observe --> Think
    Observe --> Done{Stop?}
    Done -->|yes| End[Return result]
  • Think — the brain reasons over the goal and current state, and decides the next action.
  • Act — the agent invokes a tool (e.g., call the opcp-explorer deploy API).
  • Observe — the agent reads the tool's output and updates its memory.

The loop repeats until a stopping condition is met — the subject of the next lesson.

Variant 1 — ReAct (Reason + Act)

ReAct interleaves reasoning and acting at every step. The agent writes a short thought, takes one action, observes, then thinks again. It is simple, transparent, and well suited to tasks where the next step depends heavily on the last result.

Thought: The app isn't running. I should start it.
Action: opcp.start(app="demo")
Observation: status = "starting"
Thought: Wait and check health.
Action: opcp.status(app="demo")
Observation: health = "healthy" → done

Variant 2 — Plan-and-Execute

The agent first produces a full plan, then executes the steps, optionally re-planning if something fails. This separates slow, expensive planning from fast execution and makes the intended sequence auditable before anything happens.

Plan: [clone, build, start, verify-health]
Execute step 1..4, re-plan only on failure

Good for multi-step tasks with a predictable structure — such as a full deploy pipeline on opcp-explorer.

Variant 3 — Reflexion

Reflexion adds a self-critique step. After an attempt, the agent reflects on what went wrong, writes a lesson to memory, and retries with that insight. It trades extra loop iterations for higher eventual success on hard tasks.

Attempt → fail → Reflect("build failed: missing dependency")
→ store lesson → Retry with fix

Choosing a Variant

VariantBest whenCost
ReActNext step depends on last result; need transparencyLow
Plan-and-ExecutePredictable multi-step pipeline; want an auditable planMedium
ReflexionHard tasks that benefit from learning across attemptsHigh
Note: variants combine. A Plan-and-Execute agent can use ReAct within a step and Reflexion when a step fails.

Key Takeaways

  • The agentic loop is Think → Act → Observe, repeated.
  • ReAct interleaves; Plan-and-Execute plans upfront; Reflexion learns from failure.
  • Pick the cheapest variant that reliably solves the task.
